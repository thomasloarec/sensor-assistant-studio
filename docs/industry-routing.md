# Industry routing and Claude project identity

## Business rules

Industry describes the project's final application, not the supplier's main business. The 21 labels in `industries.ts` match the supplied Quickbase list, with the corrected spelling **Automotive**. Reference labels stay in English in every interface locale; interface instructions are translated into eight languages. No Quickbase synchronization is introduced.

Routing order is **country + industry owner**, then **geographic owner** (whole country or selected city's region). There is no regional industry exception. One person may own several industries and retain geographic coverage for other applications. No exception means geographic fallback; uncovered locations stay unresolved. Explicit manually assigned CRM owners and dossier access permissions are preserved: this feature changes the suggested contact, submission routing record and booking contact.

In Business directory → person → Sales responsibilities, use **Industry responsibilities**. Select the country and industry, review the current and future owner, then confirm. Removing an exception restores geographic fallback. The server locks the assignment and checks its version; concurrent or stale transfers fail. A person with industry responsibilities cannot be deactivated or changed out of the sales role until those responsibilities are transferred or removed. All changes are audited.

With Standex places **Industry** between Company and Email. A manual selection confirms the choice. Claude suggestions require a separate confirmation; modifying questionnaire answers invalidates confirmation. The client and database both reject new submissions with a missing, invalid or unconfirmed industry. Old snapshots remain readable and unchanged. New revision routes record the industry, industry-rule version and whether industry or geography resolved the contact.

## Claude boundary

After completing the questionnaire and leaving step 1, the optional helper sends the six technical answers and project language to the `project-identity` Supabase Edge Function. It excludes contact fields, company, uploaded models, files and internal notes. Text a visitor types inside an answer remains part of that answer. The questionnaire explains this transfer and provides an off switch. No call is made while an NDA is requested. The separate internal experimental assistant and external report-translation flag are unchanged.

One bounded Claude call returns a short title and an optional industry. A forced structured tool response is validated against the 21 labels. Only a clear classification with an exact supporting excerpt can prefill the field; uncertainty leaves it empty. This is not a guarantee of model correctness: human confirmation remains mandatory. Late responses cannot overwrite manual choices or a different project's data. Manually renamed titles are preserved; autogenerated titles may be refreshed when questionnaire answers change. Failure leaves the form usable with manual industry/title entry. No fallback copies Q1's first words into the title.

The browser uses the project's public anon JWT for the Edge JWT gateway. This is a public key, not the Anthropic key or a service credential. The function is intentionally available before customer sign-in and exposes only the submitted request's generated identity. It accepts only the explicit production and preview origins. Database counters, callable only by `service_role`, limit usage to 120 requests/hour globally and 12/hour per hashed source IP. They retain no project text; subsequent calls prune counters older than two days. The global limit still applies if source-IP attribution is missing or unreliable. Responses are no-store; provider errors and input text are not logged or exposed.

## Deployment

1. Apply `supabase/migrations/20261104134443_industry_routing.sql` after the sales-territory migration. The optional pending-submission trigger is installed if `lead.customer_pending` already exists. If customer-email access is installed later, install the same `require_pending_industry` trigger then; the application validator and final revision trigger still enforce the required industry.
2. `node scripts/package-project-identity.mjs` prepares the four-file Edge bundle under `tmp/project-identity/supabase/functions/project-identity`. Deploy it as `project-identity` with JWT verification **enabled**, using the organization's Supabase deployment tooling.
3. Store `ANTHROPIC_API_KEY` in the Supabase project's Edge secrets, never in a browser environment variable. Optional model overrides: `ANTHROPIC_PROJECT_IDENTITY_MODEL`, then `ANTHROPIC_MODEL`; otherwise `claude-sonnet-4-5`. Supabase supplies its own URL and service-role key. The function uses these only to debit its private usage counters.
4. For another Supabase project, update the public anon key in `project-identity-public-key.ts`, the app's Supabase URL and the allowed origins in both the Edge entrypoint and `project-identity-client.ts`. An anon key can never replace the server-side Anthropic/service credentials. Redeploy when rotating it.
5. Publish the application after the migration is installed. Configure actual country/industry owners in the admin. Verify using synthetic questionnaire text, including an ambiguous application, then test routing and the external booking link without sending a real invitation.

Checks: `bun test tests/`, `bun test scripts/industry-ui.test.tsx` (separate process), `bun test scripts/territory-ui.test.tsx` (separate process), TypeScript, production build and the i18n inventory. SQL integration tests apply real migrations and verify permissions, stale transfers, mandatory confirmation, industry precedence, geographical fallback and bounded provider usage.

## Initial rollout verification — 4 November 2026

The migration and Edge Function are installed in the existing Sensor Studio Supabase project. Claude was exercised with synthetic answers through the public application: six French answers about an electric car charging flap produced a short French title and an unconfirmed Automotive suggestion. Confirming the suggestion enabled routing; manually selecting Medical changed the suggested contact for Rennes from Gilles Servant to Thomas Loarec. No prospect dossier or invitation was submitted during these checks.

France / Automotive was assigned to Gilles Servant through the authenticated admin interface. Existing regional assignments were preserved. Other national industry exceptions remain for Standex administrators to configure from their actual responsibilities.

Validation: 2,245 main-suite tests, 5 industry UI checks and 3 territory UI regression checks passed, along with TypeScript and the production build. The final privacy-copy adjustment passed the 30 targeted localization/privacy tests. The security advisory comparison introduced no new warnings.
